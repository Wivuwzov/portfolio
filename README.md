# TelegramAuth — Forge 1.20.1

Серверный мод авторизации Minecraft через Telegram. Не требует установки на клиент. Java 17, Forge 47.4.10.

## Установка

1. Соберите проект через Gradle (ForgeGradle 6, Java 17): `gradle build`. Для Windows доступен `build.bat` (требует установленного Gradle). Альтернатива — загрузить проект в GitHub и собрать через Actions, готовый JAR появится в артефактах запуска.
2. Возьмите `build/libs/telegramauth-forge-1.20.1-1.0.0.jar` и установите в `mods` сервера Forge 1.20.1.
3. Один раз запустите сервер, затем остановите. Появится `config/telegramauth.json`.
4. Создайте отдельного бота у `@BotFather`, заполните `botToken` в конфиге.
5. Добавьте свои Telegram username (без `@` или с `@`) в `adminUsernames`, например `"adminUsernames": ["ExampleAdmin"]`. Альтернативно укажите числовые Telegram ID в `adminIds`.
6. Запустите сервер. Администратор, добавленный по username, должен отправить боту **в личные сообщения** `/adminlink СЕКРЕТ`, где секрет указан в `adminBootstrapSecret` конфигурации. Пользователи, внесённые через `adminIds`, не нуждаются в этой операции.
7. Добавьте бота в Telegram-группу, разрешите писать сообщения. Привязанный администратор отправляет в этой группе `/setchat`. ID группы сохранится в `adminChatId` автоматически. Альтернативно заполните `adminChatId` вручную и используйте `/tgauth reload`.
8. Для самостоятельной регистрации игрок подключается к серверу, видит код и отправляет боту в личные сообщения `/link КОД`. Администратор одобряет регистрацию кнопкой в Telegram-группе.
9. На следующих подключениях бот отправляет игроку кнопку подтверждения входа **в личные сообщения**. После нажатия игрок может играть.

Секрет бота и `adminBootstrapSecret` не пересылайте другим людям. Для резервного копирования сохраняйте оба файла из `config`: `telegramauth.json`, `telegramauth-data.json`. Файл данных содержит Telegram ID, историю посещений и привязки.

## Команды Minecraft (оператор уровня 3 или консоль)

- `/tgauth reset ник` — сброс привязки и отключение игрока.
- `/tgauth ban ник` — блокировка авторизации и отключение.
- `/tgauth unban ник` — разблокировка.
- `/tgauth kick ник` — отключение игрока.
- `/tgauth whois ник` — Minecraft Display Name, Telegram Display Name, @username, Telegram ID, статус.
- `/tgauth online` и `/tgauth online 2` (также `/tgauth list`) — текущие игроки на сервере, их Minecraft-ник, Display Name и статус авторизации; страницы по 15 игроков.
- `/tgauth history 1` ... `/tgauth history 7` — все попытки входа за последние N × 24 часа, с итоговым статусом. Необязательный второй аргумент — номер страницы.
- `/tgauth reload` — перезагрузка конфигурации и Telegram-подключения.

## Команды Telegram

- `/start` — начало общения.
- `/myid` — ваш Telegram ID и ID чата.
- `/link КОД` — привязка игрока (только личные сообщения).
- `/adminlink СЕКРЕТ` — привязка администратора из списка `adminUsernames` (только личные сообщения).
- `/setchat` — выбор текущей группы как админского чата.
- `/reset ник`, `/ban ник`, `/unban ник`, `/kick ник`, `/whois ник`.
- `/online` и `/online 2` (также `/list`) — список игроков на сервере (в том числе ожидающих авторизацию), Minecraft-ник, Display Name, Telegram @username (если привязан), статус; постранично по 15 игроков.
- `/history 1` ... `/history 7` и `/history 7 2` для второй страницы.
- `/help` — список административных команд.

Админские команды доступны в заданной Telegram-группе и личных сообщениях администратора боту. В других группах они игнорируются.

## Конфиг

Файл `config/telegramauth.json` автоматически генерируется на первом запуске. В нём можно менять русский текст уведомлений и кнопок, а также `actionbarText`, `actionbarColor` (цвет `#RRGGBB`) и `actionbarDurationSeconds`.

Плейсхолдеры для Telegram-текстов: `{player}`, `{display}`, `{tg_display}`, `{telegram}`, `{id}`, `{time}`, `{code}`, `{ip}`, `{ip_line}`. Для `/online` дополнительно используются `{online}`, `{page}`, `{pages}`, `{index}`, `{status}`, `{telegram}`, `{tg_display}`. Все сообщения команды `/online` (заголовок, строка игрока, пустой сервер, подсказка следующей страницы и статусы) задаются через `messageOnline*`. Админские команды принимаются только от администраторов и только в личном чате или заданной админ-группе.

История автоматически хранится максимум 7 суток в `config/telegramauth-data.json`; журнал содержит все попытки входа, включая неавторизованные. Для записей с завершённой авторизацией статус — `authorized`. Записи о входе и статусе сохраняются локально, данные не передаются сторонним сервисам, кроме штатных сообщений Telegram.

## Замечания

- `online-mode=false` не устанавливает подлинность владельца ника при первой регистрации. Подтверждение администратором обязательно. При постоянном использовании разумно ограничить свободную регистрацию ников, например вручную утверждать личности новых игроков.
- Серверный режим ограничивает игрока до авторизации: перевод в наблюдатели, удержание на месте, отмена команд и основных взаимодействий. На сборках с нестандартными пакетами/модовыми способностями нельзя без отдельного тестирования гарантировать блокировку абсолютно всех сторонних механик.
- Для работы нужно, чтобы хостинг предоставлял исходящие HTTPS-запросы к `api.telegram.org`.
- Личный чат с ботом должен быть начат пользователем — бот не может написать ему первым без предварительного взаимодействия.
- Чтобы передать право администратора по username, требуется повторная привязка с секретом. Уже выданный Telegram ID проверяется по привязанному имени и текущему username. Постоянные `adminIds` являются более надёжным методом назначения прав.
